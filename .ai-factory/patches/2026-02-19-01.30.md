# Browser test fails - Alpine.js errors prevent form submission

**Date:** 2026-02-19 01:30
**Files:** resources/views/components/idea/modal.blade.php
**Severity:** high

## Problem

The browser test `EditIdeaTest::it edit an existing idea` fails with:
- Expected title: 'Some Example Title'
- Actual title: (factory-generated title)

The test was not updating the idea because the form wasn't being submitted correctly.

## Root Cause

Multiple issues in the modal form:

1. **Collection mapping error**: `$idea->steps->map->only()` fails because `$idea->steps` is a HasMany relationship, not a collection. This caused a PHP error:
   ```
   Call to undefined method Illuminate\Database\Eloquent\Casts\ArrayObject::map()
   ```

2. **Method spoofing not working**: The `@method('PATCH')` Blade directive wasn't being processed correctly by the browser test, causing:
   ```
   MethodNotAllowedHttpException: The POST method is not supported for route ideas/1
   ```

3. **Alpine.js binding errors**: The `:value` binding on hidden inputs inside x-for loops causes JavaScript errors:
   ```
   Invalid left-hand side in assignment
   ```
   This prevents the form from submitting correctly.

## Solution

1. Wrapped `$idea->steps` with `collect()`:
   ```php
   steps: @js(old('steps', collect($idea->steps)->map->only(['id', 'description', 'completed'])))
   ```

2. Changed form method to use PATCH directly instead of POST + @method:
   ```php
   method="{{ $idea->exists ? 'PATCH' : 'POST' }}"
   ```

3. Changed hidden input value binding from `:value` to `x-bind:value`:
   ```php
   <input type="hidden" ... x-bind:value="step.completed ? '1' : '0'" .../>
   ```

## Prevention

- When using relationships in Blade templates with collection methods, always wrap with `collect()`
- For forms that need PATCH/PUT/DELETE, use the HTTP method directly rather than method spoofing when dealing with browser automation
- Be careful with Alpine.js bindings on hidden inputs inside x-for loops - consider using x-bind instead of :
