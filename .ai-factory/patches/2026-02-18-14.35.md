# Alpine.js duplicate key warning in x-for

**Date:** 2026-02-18 14:35
**Files:** resources/views/components/idea/modal.blade.php
**Severity:** low

## Problem

Alpine.js warning: `Duplicate key on x-for` when rendering steps in the idea modal. The template used `:key="step.id"` but new steps added in the UI don't have an `id` property (only database-persisted steps have ids).

## Root Cause

The `x-for` loop used `:key="step.id"` as the key. When editing an existing idea, steps have database IDs. But when users add new steps in the UI (via the "add step" button), these new step objects only have `description` and `completed` properties - no `id`. This causes:
1. New steps to have `undefined` as the key
2. Multiple new steps all have the same key (`undefined`)
3. Alpine.js warns about duplicate keys

## Solution

Changed the key from `step.id` to `index`:

```blade
<template x-for="(step, index) in steps" :key="index">
```

Using `index` is appropriate here because:
- Each step in the form is independent
- The order doesn't carry semantic meaning (no reordering)
- Adding/removing steps is handled correctly

## Prevention

- When using `x-for` with dynamically added items, always use a stable key
- If items can be added dynamically without IDs, use index as fallback
- Consider generating unique IDs for new items if order matters
