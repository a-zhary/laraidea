# Alpine.js x-model error and UrlGenerationException in Idea modal

**Date:** 2026-02-18 14:30
**Files:** resources/views/components/idea/modal.blade.php
**Severity:** high

## Problem

1. Alpine.js error: `Expression: "step.completed ? '1' : '0' = __placeholder"` - Alpine.js failed to evaluate the ternary expression in x-model
2. UrlGenerationException: `Missing required parameter for [Route: ideas.update] [URI: ideas/{idea}] [Missing parameter: idea]` - This occurred because `$idea->exists()` was being called as a method, which returns `true` for new model instances due to Laravel's magic method `__call()`.

## Root Cause

Two issues in the modal component:

1. **Alpine.js x-model issue**: Using `x-model="step.completed ? '1' : '0'"` doesn't work because x-model requires a two-way binding to a writable expression. A ternary expression is read-only and Alpine.js cannot establish the binding, causing a parsing error.

2. **Model exists() behavior**: Laravel's Eloquent model has a magic `__call()` method that forwards method calls to properties. When calling `$idea->exists()` on a new model instance, it actually calls `$idea->exists` (the property) as a method, which then triggers `__call()` that checks `getKey()` - but this returns an empty string (not null), causing `exists` to return `true`.

The fix was to use `$idea->exists` (property access) instead of `$idea->exists()` (method call) throughout the Blade template.

## Solution

1. Changed `x-model="step.completed ? '1' : '0'"` to `:value="step.completed ? '1' : '0'"` - using one-way binding with :value instead of x-model.

2. Changed all `$idea->exists()` method calls to `$idea->exists` property access:
   - Line 13: Form action
   - Line 18: @if condition for PATCH method
   - Line 177: Submit button text

## Prevention

- Avoid using `x-model` with complex expressions or ternaries - use `:value` for one-way binding or split into simpler components
- Be careful with Laravel Eloquent's `exists` - always use property access `$model->exists` not `$model->exists()` in Blade templates
- Consider adding a static analysis rule or code review check to catch this pattern
